# Networking Notes

## 1. Локальный запуск с 127.0.0.1
Когда оба сервиса запущены локально как обычные процессы,
127.0.0.1 указывает на хостовую машину. order-service может
обращаться к product-service через http://127.0.0.1:8001 - это работает.

## 2. Неудачный запуск контейнера с 127.0.0.1
Внутри контейнера 127.0.0.1 - это обращение самого к себе контейнера,
а не хоста и не другого контейнера. Если передать
PRODUCT_SERVICE_URL=http://127.0.0.1:8001, order-service будет
пытаться подключиться к самому себе и получит 503.

## 3. Успешное взаимодействие через имена сервисов
В общей Docker-сети контейнеры видят друг друга по имени сервиса.
http://product-service:8000 и http://discount-service:8000 работают
потому что Docker резолвит эти имена во внутренние IP контейнеров.
Порты хоста при этом не используются.

## 4. Взаимодействие через host.docker.internal
Если нужно из контейнера достучаться до процесса на хостовой машине,
можно использовать специальный hostname host.docker.internal вместо
127.0.0.1. Например, если product-service запущен локально,
а order-service в контейнере: PRODUCT_SERVICE_URL=http://host.docker.internal:8001.
